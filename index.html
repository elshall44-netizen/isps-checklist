MSC-CKS-00009 · Rev 3
SSP → Substantive Cross-Referenced Review

Read the plan. Judge every requirement.

Drop in the vessel's Ship Security Plan (and the SSA, if it is a separate document) plus the blank MSC-CKS-00009 checklist. The reviewer maps the plan's structure — chapters, sections, annexes — then goes item by item through the checklist, judging whether the plan actually addresses the intent of each ISPS provision. It returns the checklist with Yes / No / N / A ticked, chapter/section/page references filled, a documented basis for every "No", and a short summary of gaps and observations.

Analysis engine

Keyword fallback

Every checklist item is judged substantively against the full plan text — checking that measures are real, ship-specific provisions rather than boilerplate — and each answer carries a chapter/section/page reference plus a documented basis for any "No". If the site operator has configured the built-in relay, AI review runs by default and the key field can stay empty; a key entered here overrides the relay. With neither, the tool falls back to keyword cross-referencing, which the auditor must verify manually.

The key stays in your browser and is sent only to api.anthropic.com. A full review makes ~7 API calls with the plan text as cached context.

Does the vessel request / carry the ABS “SEC” notation?answer required

The checklist's “Additional Requirements for SEC Notation” section also requires the Company Security Plan (CSP). Yes — those items are assessed against the provided documents. No — every item in that section is marked N/A with its SSP Doc Reference written as “NA”.
